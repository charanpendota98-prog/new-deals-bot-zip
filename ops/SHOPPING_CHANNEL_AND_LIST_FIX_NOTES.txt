Four complaints, four fixes. All in bestgaa/main_bot_new.py, all covered by

1. "neatga ravali" — a product list must not dump its links at the bottom
-------------------------------------------------------------------------
The source posts

    Premium Afghani Anjeer 500 gms at 258
    Buy Max Quantity
    Premium Mix Dry Fruits 500 gms at 258
    Buy Max Quantity
    ...
    <link1> <link2> <link3> <link4>

and the reader cannot tell which link belongs to which deal.

format_clustered_product_list() now splits the head into BLOCKS (a new block
starts on every price-bearing line; the note lines under it, "Buy Max
Quantity", an MRP line, travel with it) and puts each block's own link directly
under it, in the source's order.

The price test used to be ₹-only, which is why this exact post was never
re-laid out: the sources write "at 258", "@167", "Rs 180", "220/-". PRICE_LABEL_RE
now reads all of those. Extra links (variant links) and extra blocks are
appended rather than dropped — a lost link is a lost deal.


2. "asalu link yeh ledu" — never publish a deal with no link
-------------------------------------------------------------
Earlier rounds published a post as complete text when every link the source
wrote turned out to be a dead shortener. The user has reversed that: a post a
reader cannot click is useless to them and earns nothing.

  REQUIRE_LINK_IN_POST (default true)
    every link dead  ->  PermanentSkip("every link the source wrote is dead")
    set to false     ->  old behaviour (post it as text)

UNCHANGED: a source post that never had a link but carries the product PHOTO is
still published exactly as posted (round 13's rule). The two cases are
different — one shows the reader the product, the other shows them nothing.

The new skip reason is registered as a POLICY skip in ops/quality_audit.py and
ops/coverage_audit.py, so the auditors do not report it as a lost post.


3. Duplicates across differently-worded copies
----------------------------------------------
    "Loot : Nutriburst Collagen powder 299 (70% off)"
    "Grab : Nutriburst Collagen powder @ 299 70% off"

product_signature() already resolves both to the same key (verified), so the
per-channel dedup catches it. Nothing to change here — the two posts were
reaching the channel because the FIRST one was a linkless teaser (fix 2) and
therefore never registered a delivery. Fix 2 closes this hole too.


4. t.me/smartbuyhub11 — the Amazon Associates review channel
-------------------------------------------------------------
    SHOPPING_TARGET = "smartbuyhub11"
    SHOPPING_TARGET_ENABLED (default true)

It receives the SAME product deals as every other channel, in a
programme-safe form rendered by affiliate_safe_text() AT DELIVERY TIME (so the
stored copy every other channel gets stays exactly the source's):

  kept     product name, the price the source printed, our link
  removed  "Loot :" / "GRAB :" banners, "Buy Max Quantity", hurry/limited-stock
           urgency, "#UK no 1 brand" and other unverifiable superlatives,
           discount percentages and struck-through MRP lines, emoji shouting

Nothing is invented: every word and every number left is the source's own.

Routing rules for that channel:
  * product deals only — trick / recharge / app-promo posts never reach it
  * a post with no buyable link never reaches it
  * a post left with nothing but a link after the rewrite is skipped for THAT
    channel only (logged "SHOPPING SKIP"), the other channels are unaffected
  * if the account cannot resolve @smartbuyhub11 yet, the delivery is closed as
    done for that target instead of putting the whole job into retry — a live
    deal is never held back from the channels that DO exist

It is deliberately NOT in ALL_OWNED_TARGETS, so the bank/card-offer fan-out
does not push those posts (which are not shoppable products) at the reviewer.


Before you run it
-----------------
The bot account must be an admin of @smartbuyhub11 with post rights. Until it
is, every other channel keeps working normally and the log says
"SHOPPING TARGET UNRESOLVED".

5. "shortga ravali ga earnkaro tho" — long Flipkart links
---------------------------------------------------------
A dl.flipkart.com product link arrives ~177 characters because of lid /
marketplace / srno session noise, and it was posted at full length whenever the
shortener was rate-limited or out of quota (the shorten pass had no fallback).

compact_flipkart_product_link() now collapses it natively to
    https://www.flipkart.com/<slug>/p/<item id>?pid=<pid>
(~127 chars, no quota spent), in two places:
  * the final shorten pass (pass 1b, next to the Amazon /dp compaction)
  * convert(), before the link is handed to the shortener at all

`pid` is the product identity and is ALWAYS kept, so the link still opens the
exact item the source linked. Search/category URLs have no item id and are left
untouched for the shortener.


6. "idi manvena?" — is that link actually ours?
------------------------------------------------
Investigated. The bot runs TAGLESS (OUR_TAG = "", pinned at line 134 because
the Associates account kept getting rejected), so an Amazon link genuinely
carries no proof of ownership.

I tried tightening the provenance gate to reject bare Amazon links, and REVERTED
it: that check is what lets a legitimately-tagged link post when the link cache
is cold (right after deploy, after a prune), and tightening it dropped real
deals in the suite. Losing a deal to prove a point is the wrong trade.

Instead, an unmonetized link is now LOUD instead of silent:
    log.warning("UNMONETIZED LINK | queue=%s this deal posts a plain merchant
                 link (the affiliate network had no campaign for it): %s")
Grep the log for "UNMONETIZED LINK" to see exactly which posts earn nothing.

TO ACTUALLY EARN on Amazon you must set AMAZON_TAG (OUR_TAG) once the
Associates account is approved — that is a credentials issue, not a code one.


7. Duplicates — the real root cause
------------------------------------
    "Loot : Nutriburst Collagen powder 299 (70% off)"
    "Grab : Nutriburst Collagen powder @ 299 70% off"
    "Grab ₹298 (10KG Detergent Powder)"  /  "Loot : 10KG Detergent Powder @298"

Three separate bugs in the product signature made these sign differently:
  a) the banner word ("Loot :", "Grab ") was read as the BRAND. It is stripped
     now, colon or no colon, using the same _SAFE_PREFIX_RE the safe rewrite
     uses (so the two can never drift apart).
  b) a price written without "₹" ("@298", "at 167", "299 (70% off)") was read
     as a MODEL NUMBER. _SIG_AMOUNT_RE now reads every spelling, and a bare
     number equal to the line's own price is never a model.
  c) a product with no model number at all needed FOUR agreeing words, so
     "Nutriburst Collagen powder" was un-dedupable. Three long words is enough.

Guarded in the other direction (a signature that matches too eagerly SKIPS a
real deal), with a regression test covering:
  Airdopes 141 vs 131, S23 128GB vs 256GB, 5 Burner vs 3 Burner,
  Collagen vs Biotin, and Nivea MEN vs WOMEN — the last one was a PRE-EXISTING
  collision (gender words are now variant words, like "pro"/"fe").

ops/quality_audit.py mirrors this block; it was re-synced with
`python3 ops/sync_identity.py` and the suite enforces that they match.
